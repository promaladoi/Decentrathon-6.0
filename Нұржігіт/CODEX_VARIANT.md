# Codex candidate: tiled vocabulary reductions and RMSNorm

Branch: `codex/kernel-v1` in the hackathon platform's repository.
Development code was generated by Codex at the team's request. The existing
`solution/swiglu.py` is the organizers' example and is not claimed as our kernel.

## Changes

- `solution/vocab.py`: original Triton implementation of tiled log-sum-exp,
  class-index cross-entropy with a backward pass, and Shannon entropy.
  Vocabulary tiles are reduced to small per-row statistics instead of saving
  a full log-softmax tensor. The same cross-entropy entry point also accelerates
  Soup's per-row rewind losses without disabling its recorder.
- `solution/rmsnorm.py`: original fused forward/backward for frozen Qwen2
  RMSNorm weights, preserving normalization, cast to input dtype and weight
  multiplication in that order, including the gradient cast.
- `solution/nf4.py`: original NF4 weight decoder, fusing nested scale decoding
  and NF4 reconstruction. Backward reconstruction and bitsandbytes' existing
  CUDA decode-plus-linear forward fallback call this guarded replacement;
  the fixed model's quantization and matrix multiplication are unchanged.
- `solution.apply()` installs guarded, idempotent patches, retaining the starter
  SwiGLU patch. No task configuration, training steps, LoRA parameters, metrics,
  dataset rows, optimizer or learning-rate schedule are changed.

Six team-written kernels are recognized by the starter's source scanner. The
two starter SwiGLU kernels remain excluded. No ready-made kernel library is used.

## Scope and fallbacks

Cross-entropy acceleration handles CUDA float32 2D logits with contiguous
vocabulary columns, matching int64 class-index targets on the same device,
at least 1024 classes, `none`/`sum`/`mean` reductions and an ignore index.
Weighted loss, label smoothing, legacy reduction overrides and other input
formats use the original PyTorch implementation. Class indices must be valid
or the ignore index, as in the fixed dataset.

The NF4 path handles contiguous uint8 2D packed NF4 weights with a QuantState,
fp16/fp32 output and optional nested scale quantization. Other quantization
types, unsupported layouts and states use the original bitsandbytes function.

Entropy acceleration handles contiguous CUDA float32 logits with at least 1024
classes when gradients are disabled. RMSNorm acceleration handles contiguous
CUDA fp16/fp32 activations and frozen contiguous fp16/fp32 weights, with width
at most 8192. Trainable norm weights and unsupported cases use the original.

## Reproduction

Use `templates/kaggle_notebook.ipynb` in a phone-verified Kaggle account, GPU T4 x2
and Internet On. Set the platform repository URL and pin `COMMIT` to the candidate
code commit above. A private repository requires the `GITHUB_TOKEN` Kaggle secret
with access to that repository. Run the notebook once; do not run concurrent GPU work.

For a paired experiment that preserves previous `runs/` outputs, from the root:

```bash
python -m pytest solution -q
SOUP_APPLY_SOLUTION=1 python -m pytest tests -q
python harness/run_task.py --repeats 2 --out runs_codex_v3
python harness/check_rules.py --result runs_codex_v3/result.json
python harness/score.py runs_codex_v3/result.json
```

For repeatability, use `--repeats 2` with a separate output directory. Base and
solution are measured in the same session in base/solution/solution/base order.
