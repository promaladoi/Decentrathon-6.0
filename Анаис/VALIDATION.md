# Протокол проверки

## Условия

Одна Tesla T4 из Kaggle T4 x2, неизменённая task/task.yaml; Qwen2.5-1.5B-Instruct, NF4, LoRA r=16, alpha=32, q_proj/v_proj, dropout 0.05. Batch 4, до 512 токенов, 256 обучающих примеров, одна эпоха, 64 шага. Публичная оценка: строки 40000–40255.

## Порядок

Закреплённые зависимости → подготовка данных → GPU-тесты → harness/run_task.py --repeats 2: base_1, solution_1, solution_2, base_2. Не запускать параллельную GPU-работу. Прогрев отдельно от измерений; компиляция входит во время обучения. Агрегация: медиана полного времени, максимум пиков памяти. Harness оценивает первый успешный адаптер каждой стороны; это не среднее eval двух адаптеров.

Затем harness/check_rules.py без --skip-tests и harness/score.py. Сохранить raw result.json, checks.json, train.log, eval-логи и trainer_state.json. Checks привязан к SHA256 result.json. После изменения решения повторить измерения и проверки.

## Критерии

| Проверка | Условие |
|---|---|
| 1 | Все обучения завершились с exit code 0 |
| 2 | Нет запрещённых библиотек и установки пакетов во время замера |
| 3 | Собственные Triton-ядра реально используются в обучении |
| 4 | Доля собственных ядер не ниже 5% с третьего шага |
| 5 | Те же шаги, адаптер, настройки, токены, метрики и rewind; допустимые расхождения до 3% |
| 6 | Первый loss в пределах 1%, среднее относительное расхождение кривой до 3% |
| 7 | Eval loss не выше baseline более чем на 0,5% |
| 8 | Время и память не выше baseline более чем на 10% |
| 9 | T4, простой перед замером, один GPU, корректный учёт памяти |
| 10 | 79 регрессионных тестов Soup с патчами |

Все десять проверок обязательны. Scoring учитывает улучшение при base/solution не ниже 1,05. Два повтора описывают разброс, но не доказывают статистическую значимость.

Speedup = время base / время solution. Экономия памяти = 100 × (1 − память solution / память base). Изменение eval loss = 100 × (loss solution / loss base − 1).

Training loss и held-out eval loss характеризуют разные данные. Отсутствующие результаты не считаются PASS. Результаты starter не являются авторской оптимизацией команды.
